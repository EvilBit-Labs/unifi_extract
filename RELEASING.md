# Releasing unifi-extract

Pushing a signed `v*` tag is the only action that publishes a release.
`.github/workflows/release.yml` triggers on the tag and runs GoReleaser, which
builds every platform archive, signs the checksums with Cosign, generates the
SBOMs, updates the Homebrew cask, and creates the GitHub Release. Two follow-up
jobs attach build provenance and verify the signature.

> [!IMPORTANT]
> Do not run `gh release create` or draft a release in the GitHub UI. GoReleaser
> owns release creation; a manual release races the workflow and conflicts.

## Version numbering

[Semantic Versioning 2.0.0](https://semver.org/). Breaking changes to the CLI or
output formats bump MAJOR, new commands or flags bump MINOR, fixes bump PATCH.
A tag with a pre-release suffix (`v1.2.0-rc1`) is published as a pre-release
automatically (`prerelease: auto`).

## Pre-flight

- [ ] `main` is up to date locally: `git checkout main && git pull origin main`
- [ ] CI is green on that commit: `gh run list --branch main --limit 5`
- [ ] `just check` passes locally
- [ ] The GoReleaser config passes a snapshot build **on the version CI will use**
      (see below)

### Snapshot build

The release workflow resolves GoReleaser with `version: "~> v2"`, so CI runs the
newest v2 release, which can be ahead of the version pinned in `mise.toml`. A
snapshot on the pinned version alone does not prove the tag will build: `v1.0.1`
failed in CI on 2.20.2 with a config that 2.17.0 accepted. Run the snapshot on
the newest v2 release:

```bash
# Newest v2 version (what CI will resolve)
mise ls-remote goreleaser | tail -1

mise exec goreleaser@<that version> -- goreleaser check
mise exec goreleaser@<that version> -- \
  goreleaser release --snapshot --clean --skip=sign,sbom,publish
ls -la dist/
```

A `workflow_dispatch` run of the release workflow does the same in CI (snapshot
mode, nothing published) and also exercises signing and SBOM generation.

## Tag and push

Tag the commit on `main`, never a feature-branch head. Tags are GPG-signed.

```bash
git tag -s v1.2.0 -m "Release v1.2.0"
git tag -v v1.2.0
git push origin v1.2.0
```

Release notes are generated by GoReleaser from the commits since the previous
tag, grouped by conventional-commit type. `chore(deps)`, `docs`, `test`, and
`style` commits are excluded, so commit subjects are the changelog: there is no
`CHANGELOG.md` to update.

## Monitor and verify

```bash
gh run list --workflow=release.yml --limit 3
gh run watch <run-id> --exit-status
gh release view v1.2.0
```

Then check the published artifacts. Stop at the first check that fails: do not
extract or run a binary whose checksum, signature, or provenance did not verify.

```bash
gh release download v1.2.0 --dir /tmp/unifi-extract-v1.2.0
cd /tmp/unifi-extract-v1.2.0

# Checksums: every file listed must be present and match
sha256sum -c unifi-extract_checksums.txt      # Linux (GNU coreutils)
shasum -a 256 -c unifi-extract_checksums.txt  # macOS

# Cosign keyless signature
cosign verify-blob \
  --certificate-identity "https://github.com/EvilBit-Labs/unifi_extract/.github/workflows/release.yml@refs/tags/v1.2.0" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  --bundle unifi-extract_checksums.txt.sigstore.json \
  unifi-extract_checksums.txt

# Build provenance
gh attestation verify unifi-extract_checksums.txt --repo EvilBit-Labs/unifi_extract

# Binary reports the new version. Use the archive for the machine you are on:
# unifi-extract_<Darwin|Linux>_<arm64|x86_64>.tar.gz
tar -xzf unifi-extract_Darwin_arm64.tar.gz && ./unifi-extract --version
```

- [ ] The `EvilBit-Labs/homebrew-tap` cask was updated (needs the
      `HOMEBREW_TAP_TOKEN` secret)

## If the release workflow fails

The tag is already public either way. Do not move or delete it: a rewritten tag
breaks anyone (including the Go module proxy) who already fetched it.

A failed run may still have published. The `goreleaser` job creates the GitHub
Release and pushes the Homebrew cask; the `provenance` and `verify` jobs run
after it. Find out what is public before deciding how to recover:

```bash
gh run view <run-id>                # which job failed
gh run view <run-id> --log-failed
gh release view v1.2.0              # does a release exist, and with which assets?
```

Also check `EvilBit-Labs/homebrew-tap` for a cask commit for the tag.

- **Nothing was published** (the `goreleaser` job failed before the publish
  step): fix the cause in a PR, merge it, and tag the next patch version. The
  failed tag stays as a tag with no release.
- **A release was published and a later job failed**: the release is live,
  possibly without provenance. If the failure was transient, re-run the failed
  jobs with `gh run rerun <run-id> --failed`, then run the verification above.
  Otherwise fix the cause and tag the next patch version, and decide what to do
  with the release and cask that are already public before you tag.

## Release artifacts

| Artifact                                     | Description                          |
| -------------------------------------------- | ------------------------------------ |
| `unifi-extract_<OS>_<arch>.tar.gz`           | Binary archive (Linux, macOS)        |
| `unifi-extract_Windows_<arch>.zip`           | Binary archive (Windows)             |
| `unifi-extract_checksums.txt`                | SHA256 checksums for all artifacts   |
| `unifi-extract_checksums.txt.sigstore.json`  | Cosign v3 signature bundle           |
| `*.bom.json`                                 | CycloneDX SBOMs (per binary, module) |
